Detailed Description

File Map:
FH_Functions, Section FH_CAN (CAN), Peripheral FH_CAN07 (CAN 07)
(The CAN07 (CAN 07) could be any interested CAN of the micro-controller on which FH source code is ported)

Note
To have a clean code, FH user should have the implementation of the initialization and send functions of the CAN 07 in a separate c file
Then FH user should include the header file (.h) of the related source file (.c) here
This header file shall include the following items:
The declaration of the initialization function of the CAN 07
The declaration of the send function of the CAN 07

FH user shall use FH_CAN07_ReceiveBuf and FH_CAN07_ReceiveBufIndex in the receive ISR (Interrupt Service Routine) of the CAN 07 in a separate c file
For this to happen, FH user shall just include FH_CAN07_GlobalVariables.h there
In other word, FH_CAN07_ReceiveBuf array shall receive every byte of the received data there with FH_CAN07_ReceiveBufIndex as index of the array

FH_CAN07_SharedDataBuf_8Bits, FH_CAN07_SharedDataBuf_16Bits and FH_CAN07_SharedDataBuf_32Bits are optional and could be left intact
They could be used by FH user to set some special data like receive filters on ISR (Interrupt Service Routine) of the CAN 07 , ...
They are controllable with some commands (described in this file) through RobotFramework

Returns

Note

  ==============================================================================
                        ##### RobotFramework Example #####
  ==============================================================================
  @{MessageData} =    Create List    ${CAN07}    05    00    00    0B    B8
  &{Message}     =    Create Dictionary    DeviceAddress=${DeviceAddress_01}    Function=${Function_CAN}    Command=${CAN_Commands_ReceiveW}    Data=@{MessageData}
  ${Result}    SendMessage    &{Message}

  Comments:

  CAN07 => It indicates the CAN 07
  05 => The expected number of bytes of data to be received through the <b>ISR</b> (Interrupt Service Routine) receive buffer (FH_CAN07_ReceiveBuf) of the <b>CAN 07</b>
  00    00    0B    B8 => Example data (0x00000BB8 mili-seconds) as timeout of receiving the expected number of bytes
                          FH_GlobalTimeCounter which is a global variable is utilized to calculate the timeout
                          FH_GlobalTimeCounter shall be incremented every <b>1 mili-second</b> in an interested timer <b>ISR</b> (Interrupt Service Routine) by <b>FH</b> user
                          For this to happen, <b>FH_GlobalTimerCount.h</b> shall be included in the interested timer <b>ISR</b> (Interrupt Service Routine) file
                          If the expected number of bytes are received, the function does not wait anymore for the remaining time of the timeout
  DeviceAddress_01 => It shall be equal to the address of the device: FH_RFCommunication_DeviceAddress
  Function_CAN => It is the function in the message frame
  CAN_Commands_ReceiveW => It is the command of the function in the message frame
Warning
To be able to receive data through the CAN 07 of the micro-controller on which FH source code is ported, the FH_CAN_Init_CAN07 function shall be invoked once by RobotFramework firstly
In other words, before invoking FH_CAN_ReceiveW_CAN07 function from RobotFramework, FH_CAN_Init_CAN07 function shall be invoked in order to initialize the CAN
Note
The only solution for resetting the receive buffer index (FH_CAN07_ReceiveBufIndex) is using FH_CAN_ResetRB_CAN07 function
In other words, FH_CAN07_ReceiveBufIndex may have been already increased if any data has been already received
So it is normally required to invoke FH_CAN_ResetRB_CAN07 through RobotFramework to reset the receive buffer index (FH_CAN07_ReceiveBufIndex) before invoking FH_CAN_ReceiveW_CAN07
